# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this package.

## What this is

`@my-tuums/db` — the Postgres + Drizzle data layer of the monorepo. It owns the connection (one process-wide postgres.js pool), the full schema (hand-written app tables plus generated BetterAuth tables), the committed migration history, and the helpers that resolve and guard test databases. It serves data only: no HTTP, no business logic.

## Key files

- `src/index.ts` — module-scope `DATABASE_URL` read, the shared pool, the `db` handle, and `closeDb`/`pingDb` for graceful shutdown and `/health`.
- `src/schema/app.ts` — hand-written tables (`post`, `post_like`, `follow`) and relations. Its inline comments record the load-bearing decisions (composite PKs, `timestamptz`/`precision: 3`, index ordering) — read before touching anything here.
- `src/schema/auth.ts` — GENERATED by the better-auth CLI. Never hand-edit; `pnpm db:generate:auth` regenerates it and `scripts/patch-auth-schema.mjs` post-processes it (that script's header explains what and why).
- `src/schema/index.ts` — barrel joining both schema halves; the `schema` entry `drizzle.config.ts` and `src/index.ts` point at.
- `src/migrate.ts` — `runMigrations(folder)`, the library the server's pre-deploy step calls.
- `src/testing.ts` — test-URL resolution (`resolveTestDatabaseUrl`, `databaseNameOf`, `maintenanceUrlFor`) and `assertTestDatabase`, the destructive-helper guard.
- `drizzle.config.ts` — drizzle-kit config (schema in, `drizzle/` out).
- `drizzle/` — committed migration SQL + snapshots. Generated by `db:generate`; ships inside the server Docker image.
- `scripts/setup-test-db.mjs` — creates and migrates the `_test` database (`db:test:setup`); `scripts/patch-auth-schema.mjs` — post-processes generated `auth.ts`.

## How it connects to the rest of the monorepo

Subpath exports (all source `.ts` — no build step; consumers compile or tsup-inline it): `.` (`db`, `Database`, `closeDb`, `pingDb`), `./schema` (tables/relations), `./testing` (test helpers), `./migrate` (`runMigrations`).

- `packages/api` — every procedure's `Context` carries the `db` handle; procedures query tables from `./schema` (see `src/posts.ts`, `src/users.ts`).
- `packages/auth` — better-auth is configured over the same `db` handle (`src/index.ts`, and `src/testing.ts` for its tests).
- `apps/server` — `index.ts` wires `closeDb`/`pingDb` into graceful shutdown and `/health`; the pre-deploy entry `src/migrate.ts` calls `runMigrations` with `MIGRATIONS_DIR` (default `packages/db/drizzle`).
- Vitest configs (`packages/api/vitest.config.ts`) and Playwright (`e2e/`) import from `./testing` to compute the test URL *before* anything imports the root subpath, which throws without `DATABASE_URL`.

## Load-bearing decisions — do not break

- **Import-time env read.** `src/index.ts` evaluates `DATABASE_URL` at module scope and throws when unset. That is why `./testing` exists as a separate entry point.
- **TLS rule.** TLS is required for dotted hostnames and disabled for loopback and single-label (Docker Compose-internal) hostnames. See the `requiresTls` comment.
- **Schema split.** App tables must stay in `app.ts`; regenerating the auth schema would otherwise wipe them.
- **Composite PKs are the idempotency mechanism.** Uniqueness for likes/follows lives in the PK so handlers can use `onConflictDoNothing` instead of read-then-write races.
- **`timestamptz` + `precision: 3` on every `created_at`.** Microsecond precision would silently drop rows from keyset cursors (JS `Date` carries only milliseconds). Do not "optimise" it.
- **Indexes mirror the cursor.** All are ordered to match the keyset pagination in `packages/api`; `post_created_idx` is deliberately partial (top-level posts only).
- **Migrations are committed and shipped**, applied once by the pre-deploy step — never at server boot (N replicas would race the same DDL).
- **Destructive helpers refuse anything not ending `_test`** (`assertTestDatabase`, `setup-test-db.mjs`).
- **One pool per process.** `db` is a singleton; integration suites share it (the api suite runs `fileParallelism: false`).

## Commands

All package scripts load the root `.env` via `dotenv -e ../../.env`.

- Root-level (turbo): `pnpm db:generate`, `pnpm db:push`, `pnpm db:test:setup`.
- Package-level (root has no alias for these): `pnpm --filter @my-tuums/db db:migrate|db:check|db:studio|db:generate:auth`.
- `pnpm db:test:setup` — create + migrate the `_test` database (needs `DATABASE_URL` in `.env`).
- `pnpm --filter @my-tuums/db lint` / `typecheck` — eslint / `tsc --noEmit`.
